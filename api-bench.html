API Bench

I built API Bench to see how APIs behave in practice, not only how their documentation describes them. Its Compare Models page sends one prompt to several AI providers side by side.

Open Compare ModelsOpen API BenchView the code on GitHub
Background
Comparing AI models means a different console, key and format for each provider. A screenshot of a chat window doesn’t show the settings, the raw response or the timing.
Hypothesis
Sending the same prompt and settings to every provider, and keeping every request and response, makes comparisons fair and repeatable.
Key decision
API keys stay in the visitor’s browser, with no server in between. The trade-off: five providers that block browser calls are left out until a safe proxy exists.
Implementation
Plain HTML and JavaScript on GitHub Pages. Eleven providers, including Gemini, Groq, OpenRouter, OpenAI and Anthropic. Single-turn and conversation modes; Markdown and JSON exports.
Testing and validation
53 automated browser checks run before each release.
Next steps
Planned: a small proxy for the blocked providers, and pass/fail scoring for answers.

Product decisions and trade-offs

Error labels

A setup error isn’t a model failure

A batch-only model’s error looked like the model failing. Errors are now labelled by cause: key, rate limit, credits, unsupported model or network.

Reasoning models

Answers lost to hidden reasoning

Some models used their whole answer budget on hidden reasoning and returned nothing. The tool shows reasoning tokens and suggests raising the limit.

Unsupported settings

Retry without the rejected setting

Claude Haiku 5.5 rejects the temperature setting. The tool resends without it and keeps both attempts on record.
